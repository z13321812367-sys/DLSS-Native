RTX video, end to end.

DLSS Native is a video pipeline for Super Resolution, Frame Generation and HDR-aware processing, built around one D3D12 context and one media timeline.

The point is simple: keep frames on the right GPU path, keep timestamps intact, and verify the file that comes out.

Architecture

One frame stays one story.

Source timestamps enter the pipeline once. The same sequence-scoped RTX context then owns optical flow, neural processing, scheduling and the handoff to the output side.

Why native

Less shuffling. More control.

Video performance is not just model speed. It also depends on where frames live, how long they live there, and whether timing survives every stage.

01 · GPU PATH

Keep surfaces on the GPU.

Shared D3D12 ownership lets neural stages exchange native surfaces without making CPU memory the default handoff point.

Adapter · queue · feature sessions · shared surfaces
02 · TIMING

Use the timestamps you actually have.

Frame PTS drives scheduling. Average FPS is useful metadata, but it is not a replacement for a real media timeline.

PTS-aware scheduling · reordered output · EOS handling
03 · HDR

Treat HDR as image data.

Precision and transfer semantics stay part of the processing path instead of being reduced to a few container flags.

High-precision surfaces · explicit publication boundary

Engineering focus

Built for actual video runs.

Short demos can hide scheduling and output problems. The pipeline is being tested as a media system: frame counts, PTS coverage, reordered encoding, drain behavior and final container output all matter.

Performance numbers will be published when the direct encoder path and long-run acceptance are complete.
